## B. 从零配对（G1 核心）

当前设备使用的是 NVS 里的旧 token，必须先撤销，才算真正验证配对。

1. [ ] 记录当前设备：`GET http://127.0.0.1:8765/device/list`
2. [ ] 撤销当前设备：
   ```powershell
   Invoke-RestMethod -Method Post http://127.0.0.1:8765/device/revoke `
     -ContentType "application/json" `
     -Body '{"id":"dev_938166bb803c"}'
   ```
3. [ ] 开始计时，观察设备多久进入未授权/配对状态
4. [ ] PC UI 点击“生成配对码”，记录 6 位码和过期时间
5. [ ] 在设备上输入 6 位码并确认
6. [ ] 记录从生成配对码到设备显示已连接的总耗时
7. [ ] Bridge 显示 `connected=1`，设备进入空闲状态
8. [ ] 重启设备，确认 token 保留并自动重连（启动时间不计入 5 秒重连）
9. [ ] 恢复出厂，确认 token 与 WiFi 都被清除

**通过标准**：
- 撤销后 ≤10 秒设备进入未授权状态
- 首次配网 + 配对 ≤2 分钟（不含输入 WiFi 密码）
- 配对码一次性、2 分钟过期、过期后明确提示
- token 只返回设备一次，PC UI/日志不显示明文 token

**实测记录**：撤销耗时 ____ 秒；配对总耗时 ____ 秒；重启重连 ____ 秒。

## D. L2 审批（设备可批准/拒绝）

准备一个工作区内临时文件，例如 `pager_workspace/test_delete.txt`。

- [ ] 在 PC UI 发指令，让 Hermes 删除该文件，触发 L2 审批
- [ ] 设备审批页显示 L2、摘要、批准/拒绝按钮
- [ ] 点“批准”，确认文件被删除，状态回到 DONE
- [ ] 重新创建文件，再触发一次，点“拒绝”
- [ ] 确认文件仍在，状态显示已拒绝/未执行
- [ ] 审批超时后，确认不能重复批准

**通过标准**：批准真实生效；拒绝真实阻止；重复点击/超时不会重复执行。

## E. L3 审批（设备只能拒绝，PC 才能批准）

- [ ] 触发一次工作区外文件修改，确认风险等级为 L3
- [ ] 设备审批页显示“回电脑批准”，批准按钮为禁用态
- [ ] 点禁用按钮，确认无反应
- [ ] 点“拒绝”，确认操作未执行
- [ ] 再触发一次 L3，在 PC UI 点“批准”，确认操作成功
- [ ] 检查 Bridge 日志：设备侧 L3 allow 被拒绝，PC 侧 allow 成功
- [ ] 检查设备屏幕：不显示完整原始命令/完整路径，只显示摘要

**通过标准**：设备端 L3 批准在 UI、固件、Bridge 三层都失败；拒绝可用；PC 批准可用。
