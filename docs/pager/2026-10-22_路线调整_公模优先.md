# Pager 路线调整：公模优先，功能与测试优先

- 日期：2026-10-22
- 状态：已确认
- 关联：[产品定义 v0.1](../产品定义_Agent遥控器_v0.1.md) · [G0 报告](../pager_bridge/G0_report.md) · [固件烧写与 G1 联调](2026-10-22_Pager固件烧写与G1联调.md)

---

## 1. 决策

1. 首批不等待自研 4 层板、3D 打印壳或开模，直接采用现成公模整机销售。
2. 公模已有圆屏、较大方形屏等版本；后续按屏幕形态出多个 SKU，首版不再锁死单一外形。
3. 硬件选型、结构、开模暂不作为关键路径；当前只保留“能跑功能”的硬件抽象和测试。
4. 资源优先级：**功能闭环 > 真机测试 > 多版本适配 > 小批量销售 > 认证/量产**。
5. 原 G2 的“自画 4 层板 + 3D 打印壳”交付物取消；G2 改为“公模小批量 + 多版本适配”。

具体公模型号、屏幕分辨率/接口、触摸/音频/电池配置，等进入多版本适配时再锁定，不阻塞当前 P0 功能开发。

## 2. 调整后的路线图

| 阶段 | 新定义 | 交付 | 决策门 |
|---|---|---|---|
| **G0 Discovery** | 技术验证 + 商业验证 | 现有 bridge + 公模样机；用户访谈/试用 | 原 G0 指标；可与 G1 并行，但进入 G2 前必须关闭 |
| **G1 功能闭环** | 开发板/公模样机把功能跑通 | 配对/撤销、配网、PTT、审批、L3、Pager 模式；20 台内测；2 周日记录 | ≥8/20 每周使用 5 天；≥3 次审批/天；NPS ≥40 |
| **G2 公模小批量** | 公模多版本 + 小批量销售 | 圆屏/方屏适配；50–100 台；包装、说明书、售后 | 30 台预购或 10 个付费试点 |
| **G3 认证与稳定** | 认证、供应链、质量 | SRRC/FCC/CE（按模组/公模方案）；BOM；返修率 | 认证通过；BOM ≤$32；退货率 <10% |
| **G4 放量** | 量产与正式发布 | 500–1000 台 | 300 台预购；现金流转正 |

> 关键变化：G2 不再以“自研硬件”为前置条件。硬件是现成变量，软件体验、审批安全和稳定性才是当前产品差异化的主战场。

## 3. 功能优先级

### P0：没有它不能交给外部用户

**设备接入与生命周期**
- 从零配对：`/device/pair/start` → 6 位码 → 设备确认 → token 只返回一次。
- 撤销 token 后 ≤10 秒设备进入未授权状态。
- 断电重启后 token 保留；恢复出厂后 token 和 WiFi 都清除。
- 断线重连 ≤5 秒；Bridge 重启、WiFi 切换、IP 变化可恢复。
- mDNS 失败时手动 IP 可用。

**配网**
- SoftAP 配网页；仅 2.4 GHz。
- 密码错误、5 GHz、防火墙拦截都有明确提示。
- 首次配网 + 配对 ≤2 分钟（不含用户输入 WiFi 密码的时间）。

**语音**
- PTT 按住说话，松手发送；无唤醒词。
- STT 上行、TTS 回传、打断/取消。
- 真实噪声环境下的识别率与延迟测试。
- 语音失败时可回退到 PC 文字输入。

**审批与安全**
- L0–L3 风险分级；设备/PC 来源区分。
- L3 在固件层、协议层、Bridge 层都拒绝设备批准；只能 PC 批准。
- 审批 TTL、幂等、重放保护、审计日志。
- 设备屏幕不出现原始命令；只显示摘要和风险等级。
- “Pager 模式”预设：强制 `approvals.mode=manual`；禁用或沙箱化 `execute_code`。
  - 本机现状已确认：Hermes 全局配置是 `approvals.mode: smart`，且 `command_allowlist` 包含 `execute_code`，这正是绕过审批的根因。
  - 实施时给 Pager 单独建 Hermes profile / config，不直接改用户全局配置；启动时检查配置，不满足就拒绝进入 Pager 模式并提示。

**设备 UI**
- 两页结构：状态页 + 审批页；左右滑页。
- 审批队列、L2 批准/拒绝、L3 禁用批准、设置页。
- WiFi/电量/连接状态、亮度/音量、设备信息、恢复出厂。

**稳定性**
- 重启、断网、Bridge 崩溃、token 撤销后的恢复路径。
- PC UI 只绑 `127.0.0.1`；设备入口全部鉴权。

### P1：多公模版本

- 显示抽象层：圆屏/方屏、分辨率、安全区、布局变体、1×/1.5×/2× 预览缩放。
- 触摸、音频、电池、充电的硬件抽象与自检。
- 按 SKU 构建固件；工厂测试模式。
- OTA 升级与回滚。
- PC Bridge 设备管理、审计页、多 Agent Profile；Hermes 稳定后接 Claude Code。
- 包装、快速入门、售后说明。

### P2：规模化

- 多设备管理、云端中继、手机伴侣、团队权限、用量分析。

## 4. 测试计划

### 4.1 自动化

现有：
- `test_risk.py`：L0–L3、远程审批策略、来源策略。
- `test_summary.py`：审批摘要。
- `test_g1.py`：配对、TLS、设备 API 回归。

需要补：
- 配对生命周期：生成、确认、过期、撤销、重放。
- token 持久化/恢复出厂。
- 审批 TTL、幂等、重复点击、并发审批。
- Pager 模式：`execute_code` 拦截/沙箱。
- 固件构建与屏幕布局回归。

### 4.3 用户测试

- 20 台内测，2 周日记录，按原 G1 指标验收。
- G2 前做 5–10 个付费试点，验证真实使用频率和付费意愿。
- 重点记录：PTT 成功率、审批响应时间、屏幕可读性、佩戴/放置场景。
